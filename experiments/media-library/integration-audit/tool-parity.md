## Identity and media contracts

- Preserve **record `id`, canonical `assetId`/typed `ref`, `jobId`, `sourceOutputId`, `savedAssetId` and `source` separately**. API assets emit public identity from `publicId`; recent outputs emit `{type:'job-output', jobId, outputId, kind}` (`assets/route.ts:60–79`; `recent-outputs/route.ts:86–105`). Browser display IDs are not proof of ownership.
- Extend shared browser types/projections without erasing those fields, and make consumers use canonical identity explicitly: preserving `assetId` alone does not correct Studio's current `canonicalMediaAssetFields(asset.id)` call. Image insertion accepts explicit ref/public asset identity (`image-reference-slot-state.ts:9–16`); creator selection supports public assetId or exact job/output pair (`creator-source-selection.ts:14–27`). Do not infer output index from card order (`frontend/src/lib/toolbox/contract.ts:7–11`).
- Keep exact `url` original as action/source identity. Poster, short preview and playback derivative have separate fields. Gallery mapping chooses each clicked member's original (`frontend/components/library/gallery-media-assets.ts:5–15`); original qualification matches that URL and ready status (`frontend/lib/video-continuation.ts:37–47`).
- Read grants (`accessUrl`, `thumbnailAccessUrl`, `previewAccessUrl`, `playbackAccessUrl`) are response-only, never identity (`frontend/lib/media-read-access.ts:1–7`). Upload grants currently expire after 300 s (`frontend/server/media-library/read-access.ts:7–17`); a persisted draft/handoff must be resolvable without treating a temporary grant as the canonical source. Signed/private posters stay outside public optimization.
- Preserve MIME, byte size, width/height, measured duration and `mediaFacts` where provided. Known incompatible sources are blocked; unknown facts remain explicitly unverified; long temporal sources may require excerpt preparation (`frontend/lib/media-input-eligibility.ts:19–30,47–125`). Collection membership cannot make a media input eligible.
- A typed Studio destination is not a normal `media` handoff: canonical assets resolve first; recent outputs are promoted only on opening; apply uses sequence/revision/idempotency and requires explicit insert/replace. Replacement retains timing and needs sufficient measured temporal duration (`StudioMediaAction.client.tsx:58–107`).

## Picker, popup and draft lifecycle to preserve

1. **Staged single selection:** `ReferenceLibraryPicker.client.tsx:25–68,93–110` keeps chosen original separate from composer, supports clear/cancel, disables busy confirmation, prevents duplicate submit and retains failure. Filtering by search does not remove an existing choice if its exact id+URL still exists in loaded assets. It does not currently provide an independent full preview action.
2. **Scope reset:** `AssetLibraryBrowser.tsx:109` remounts selection for destination/source/kind. Closing/reopening the surrounding modal discards the pending picker choice; it does not revert accepted composer assets. Changing account, source or actual original invalidates stale choices (`tests/reference-picker-dom.test.ts:172,246,317`). Do not call this durable multi-selection today.
3. **Immediate character mode:** `ImageLibraryModal.tsx:331–338` toggles owned character references immediately and shows Done, with live capacity; Cancel cannot silently acquire staged semantics. Normal image mode confirms one selected image. Preserve separate original character/look payload even when displaying its thumbnail (`:243–256`).
4. **Uploads remain owned operations:** Video workspace supplies field/Kling import callbacks and contextual eligibility (`WorkspaceRuntimeModals.tsx:182–225`). Generic modal imports one file, image preparation, video multipart, and audio only via supplied callback (`AssetLibraryModal.tsx:313–396`). A successful import currently selects through its owner rather than merely adding a global queue row. Do not accidentally insert twice when adding a common import queue.
5. **Reference popup → Library:** `frontend/components/composer/WorkspaceReferenceSection.client.tsx:111–115` synchronously closes/unlocks the reference popup before opening Library and restores a connected opener. Preserve focus trap, Escape/backdrop, return focus, body unlock and explicit field/slot target (`:200–214`).
6. **Video draft preservation:** `useWorkspaceSourceModeAssets.ts:32–103` parks complete ready assets, mode settings and excerpt identity/ranges by account/model/Create/Modify/Extend/Reframe/Retake. Upload/excerpt activity blocks departure; storage commit happens before setters. Shared reference edits remain authoritative. Do not duplicate this state in a common picker.
7. **Image draft preservation:** account-scoped snapshot writer/hydration and per-slot upload retirement stay in `image/_hooks/useImageComposerPersistence.ts` and `useImageReferenceSlotLifecycle.ts`; insertion remains `useImageReferenceSlots.ts:357–435`. Lifecycle writer tests cover pagehide/hidden/unmount, not just the debounce (`tests/image-composer-persistence-lifecycle.test.ts:29–71`).
8. **Handoff is a pending confirmation:** one session record per tab, exact account/destination/token, max 32,000 chars and 10-minute TTL; consumption removes storage even on invalid scope (`frontend/lib/media-handoff.ts:24–45`). `useMediaHandoff.ts:7–28` tolerates StrictMode and does not reopen after close. Reopening that URL/reloading does not restore an unaccepted handoff. Do not market it as a saved draft.
9. **Prototype lifecycle differs:** ToolDialog remains mounted (`App.tsx:152`), retains per-target/role committed baskets across close/search/preview/import, while Cancel drops uncommitted basket edits (`ToolDialog.client.tsx:19–100,116`). It is memory-only, unscoped by account, and survives neither page reload nor component retirement. Its destination roles/maxima are sample data, not product capabilities.
10. **Specialized drafts/recovery:** Recast persists account-scoped image/file/range/settings draft and blocks portrait handoff during uncertain purchase (`useRecastDraft.ts:5–73`; `CharacterStudioRecast.client.tsx:120–146`). Creator pre-prepare selections are local workbench state; submitted/recovered operation identity has its own session owner (`creator/useCreatorOperation.ts:35–68,125–160`). Subtitle unsaved text/revisions must survive read refresh and unrelated picker cancellation.
11. **Studio purpose matters:** `ImageReferenceLibrary.client.tsx:31–67,139–178` distinguishes conversation references from timeline media, supports saved/recent/Characters and promotes recent output with the canonical owner. Its current filter identity includes query, so a search change invalidates pending selection (`:59–63,93–119`). Conversation attachments persist separately from picker/timeline (`useConversationMediaShelf.ts:39–78`).
12. **Localization:** reuse `reference-picker-copy.ts`, `workspace-reference-copy.ts`, `media-action-copy.ts`, creator copy and I18n. Existing surfaces support EN/FR/ES; prototype is French only. `UpscaleLibraryModal.tsx:67–81` localizes close but omits the browser `locale` prop, whose default is EN (`AssetLibraryBrowser.tsx:114`): common-shell adoption should cover that existing gap explicitly.

## Integration constraints / bounded rollout plan

1. Define a lossless common media read model and adapters first; retain all identities/facts/access/display fields and source capabilities. Add contract fixtures shaped like actual saved/recent responses, including private upload and multi-output jobs. Correct the three verified mismatches through their owners before calling parity achieved.
2. Keep one common library/collections browser and separate selection intent: account, destination/model/mode, typed role/fieldId, slot/index, accepted kinds, cardinality/reference budget, exact eligible source, current selection and insertion callback. Derive constraints from existing owners; use prototype roles only for demonstration.
3. Adapt the current confirmed single picker, immediate Character toggles, ordered multimodal references and owned-generation picker separately. Do not impose prototype's max 4/12 or implement cardinality with kind filtering alone. Keep optional references, masks where genuinely supported, guide/keyframe exclusions, Kling elements and start/end roles.
4. Route page, gallery, recent rail, lightbox and tool-result actions through compatible destination projections; retain 14 shared handoff destinations plus separate Studio, specialized Character/Recast/Storyboard/Audio navigation and Draft Final actions. Hide/disable using existing auth/release/runtime/profile facts; preserve meaningful unavailable states.
5. Retain each destination's draft/insertion/qualification owner and exact quote lifecycle. Opening library, preview, collection, role or destination never executes a model, confirms a quote, auto-promotes every recent item or writes a timeline. Source/settings changes invalidate only their corresponding quote via existing APIs/hooks.
6. Common preview/import overlays must suspend rather than discard the pending picker context, restore focus, avoid nested active modal locks, and reject late work after account/destination/role/media change. Use original references for acceptance and signed read grants for reading; refresh grants through owning reader instead of persisting expired display links.
7. Ship by adapter cohorts: shared library and standard single pickers; image/video dynamic roles; tool sources/results; specialized Studio/Character/Recast/Storyboard/Audio. Each cohort requires its old entry points and options to remain reachable. No production rollout or new specialized destination is authorized by this audit.
