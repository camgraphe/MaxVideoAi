# Application presentation and preferences

## Scope and ownership

`AppExperienceRoot` enables the product presentation on `/app`, `/dashboard`, `/settings`, `/jobs`, `/billing` and `/account/connections`, including descendants. It lives inside the existing core providers. `frontend/src/styles/app-experience.css` owns scoped application colors, type, navigation and surface composition. Shared marketing tokens and primitives retain their defaults outside this wrapper. The locally licensed Geist font is registered in the core layout without a global preload; provenance is beside the font.

Use responsibility classes such as `app-model-strip`, `app-prompt-surface`, `app-reference-surface` and `app-result-details`. Prefer an open layout with dividers and a single input surface. Avoid creating another nested card to restyle a section. Keep enabled/disabled, focus, selected and reduced-motion states explicit. Product navigation groups existing URLs by use and provides five labelled mobile destinations (Create, Media, Tools when enabled, Activity and Account), plus Video/Image/Audio creation tabs and the complete menu. `app-navigation.ts` owns destinations and active selection; `AppNavigation.client.tsx` renders both rail and mobile variants. `app-shell.css` owns only the application shell. Short desktop windows retain a scrollable rail and 44px targets.

`AppSiteMenu.client.tsx` owns the native modal, focus restoration and its scroll entry. The header shows the official MaxVideoAI mark, the existing account-owned wallet and ChatGPT/Claude marks. `AppAssistantConnections.tsx` links to localized connection guides in separate tabs; it must not imply an authenticated connection or vendor endorsement. Codex and all-assistant access remain available. Marketing navigation remains unchanged outside app routes. Missing wallet data is distinct from a zero balance.

`useHeaderAccountState` owns wallet loading separately from authentication readiness. Wallet settlement does not wait for the independent admin read. Keep a usable balance visible during refresh; show loading while the first read is pending and unavailable only after a settled failure. Request generations reject stale responses after account changes, invalidation, sign-out and unmount; changing accounts clears both the previous balance and admin state.

`WorkspaceCreationHeading` is shared by the video boot/runtime and image creation surfaces. Empty creators retain model selection and show `WorkspaceEmptyPreview`, a compact pictogram and labelled output location, without mounting an empty media element. The audio preview consumes existing active-job/result owners and keeps that location through submitting, pending, running, failure and completion; completed native audio/video readers use `preload="none"`. Existing posters, loading results and actual readers preserve their media contracts. `AppClient` and `ImageWorkspace` remain orchestrators; generation, pricing, references, drafts and polling remain in their original hooks. Engine dropdown rendering remains separate from interaction state; its mobile family picker uses the horizontal brand strip, its geometry is viewport-bounded and keyboard model selection only visits mounted enabled options.

## Creator input ownership

`Composer` retains its shared default; workspace density opts into progressive references, a labelled 96px prompt and a separate command row. Single-prompt mode associates a label to its textarea; multi-prompt mode names a group with individually labelled scene inputs. `WorkspaceReferenceSection.client.tsx` owns compact Start/End/References commands and a bounded occupied summary. `workspace-reference-commands.ts` identifies actual video keyframes; image-creation sources and masks retain their field names. Missing required sources stay visible below the commands. `WorkspaceReferencePopup.client.tsx` opens the existing `AssetDropzone` controls on demand, with full inventory and exact sparse field/index callbacks. `WorkspaceAssetSlot.client.tsx` keeps replace, library and remove buttons as siblings of native readers so playback cannot trigger uploading.

Reference popups use the existing modal focus owner. Library handoff unmounts the reference popup, restores its connected command and releases its body lock before calling the existing library handler. The image route retains its own lazy `ImageLibraryModal`, with the same focus/lock behavior and an import close guard. Keep the image mobile gallery inside the shell column: the core layout switches to a horizontal row before the image workspace enables its desktop rail.

Known reference role titles and capacities are localized by the presentation copy helper, including required-role summaries. Custom source and mask labels retain their authored text; localization must not rewrite the field objects or their insertion identities.

Model-specific schema and budget owners remain authoritative. Do not copy prototype capacities into production. Family and variant selection still use the canonical engine picker. Options delegates to the existing video settings and lazy image advanced panel; existing hidden/default behavior is preserved for other consumers. Stale or recalculating quotes are not presented as the current price. Audio retains its four modes and its existing quote controls, with the generation dock above mobile navigation and inside the desktop work area.

Core and image settings bars accept a `trailingControl` so Options wraps with the actual settings. Workspace Composer keeps savings/status and quantity/generation on a separate responsive row; labels may wrap while the displayed price remains intact. Portal settings menus opt into the app theme and 44px choices, with explicit padding so mobile navigation clearance does not leak into the popup. Pricing, generation callbacks and advanced-panel state remain owned by the existing routes.

The catalogue summary derives exact eligible identities and families from the existing selector inputs through `engine-select-catalogue.ts`; it adds no request or registry policy. Current models remain recommended by default, legacy models remain reachable through the explicit filter, and a selected legacy model stays visible. Search explains matching models hidden by that filter. Closed workspace controls keep full model/provider names and a distinct variant choice, stacking below 360px and retaining 44px targets.

`workspace-reference-availability.ts` distinguishes blocked addition from management of existing media. The field mapper preserves upstream restrictions before the compact commands and Recents consume them. A restricted collection can still expose its allowed fields; existing media remains removable. Commands use guarded `aria-disabled` so removing the final locked asset does not destroy the popup's focus-restoration target. Keep the original field objects, validators, callbacks and sparse indices authoritative; do not infer a universal start/end-versus-references rule from Seedance's behavior.

`GenerationPendingStatus` is shared by the video overlay and audio preview. It presents confirmed stage, elapsed time, total estimate and the age of the last successful check. Only explicitly provider-sourced percentages may appear. Engine averages are optional and load separately from the catalogue; measured totals are not multiplied by quality or mode factors. The presentation clock never polls, and completed outputs are never held behind an estimate. See `generation-observations.md` for timing provenance, incomplete sample coverage, status merging and polling ownership.

## Library and results

`useLibraryPageData` owns account-scoped SWR infinite listing and controlled server search. The presentation consumes that contract; it must not reintroduce search limited to already loaded items. Listing APIs add `nextCursor`/`hasMore` while retaining existing arrays. Search, kind, source and exact owned job filters apply before pagination; current and legacy origins deduplicate before cursor boundaries. The executable library/PostgreSQL tests cover the query contract.

Grid readers keep thumbnails/previews separate from originals, and incidental video only mounts for playback intent. Download/reuse/save actions retain original assets. The result lightbox uses `useAccessibleModal` for focus entry, containment, Escape and restoration. Primary actions and Close remain named and visible on mobile; secondary metadata can be expanded.

Pending entries carry generation observations and timing through `GroupViewerModal` into the same `GenerationPendingStatus` presentation as the main reader. Legacy progress values cannot become displayed percentages. Optional output listings continue to prefer durable `storage_url` over provider `url` for both projection and deduplication.

The video workspace's Recents view reuses the account-scoped library feed through `useWorkspaceRecentMedia`. Opening it or choosing Refresh revalidates the shared key without adding a polling loop. `RecentMediaList.client.tsx` is presentation-only; insertion and desktop drag shortcuts go through the same role selection, original asset and reference-budget owners. Required metadata comes from an authenticated, owned-asset read; incomplete or incompatible media cannot bypass validation. The card interface is destination-neutral for a future Studio integration, but this branch only inserts into real reference fields.

## Account preferences

The settings page remains a route shell. `AccountSettingsPanel` renders the form, `useAccountNameForm` owns lifecycle and `account-preferences.ts` owns validated name updates. Names are trimmed, 1–80 characters, and only `name`/`full_name` metadata is patched. The update uses a captured and verified bearer token, preventing a later ambient session switch from retargeting the write. User changes reset stale form responses. Email is read-only in this lot.

Same-user metadata can change between cached and verified authentication results. The form reconciles that name while pristine, preserving dirty edits and pending saves; account changes retain their separate invalidation path.

`useThemePreference` owns `light`, `dark` and explicit `system` preference, synchronizes header/settings and other tabs, and falls back to in-memory state if storage is unavailable. Missing or invalid `mv-theme` retains the existing light default. System changes are followed only when the user chose System. Locale uses the existing app locale switch.

## Qualification boundaries

Desktop/mobile screenshots come from real rendered components. Library pagination, result states and the populated account form can be exercised with explicitly local fixtures; these do not prove live login, account saving, paid generation, upload, export or Safari behavior. Keep temporary fixture routes out of production. Initial loading changes require comparable production baseline/candidate evidence; local Lighthouse is synthetic and is not field INP or production Core Web Vitals.

The 7 September connected-app integration passed 4,429 tests with no failures or skips, localization parity, lint, exposure checks, TypeScript and a production build (861 static pages). The final source check includes the account hydration, pending lightbox, localized reference and durable output corrections. The build used dummy public Auth configuration and no database/provider/payment secrets. It ran under the available Node 23.9.0 rather than the repository's Node 22 target; engine/experimental, Webpack cache and unchanged Supabase Edge-runtime warnings remain qualification notes. Temporary fixture routes were removed before building. Browser checks covered 320/390, tablet 900, desktop 1440 and short landscape 844×390, including the corrected image gallery placement and stateful removal/focus recovery. The final lightbox correction received an additional 1280px check with local observations. This does not establish production timing quality or a Core Web Vitals improvement.

Studio canvas redesign and saved timeline assembly remain a separate integration lot. The current optional MCP montage tool prepares a read-only edit plan with `persisted: false`; see `mcp-montage-preparation.md`. Do not expose it as a saved project or enable discovery by default.

The subsequent catalogue/reference validation at `7f7ac5858` passed 4,448 tests and an 861-page build, with a clean scoped final re-review. A dedicated expiring Neon data branch qualified connected wallet, history, membership quotes, published catalogue and completion-event averages; the preview omitted provider/payment/storage write credentials. Native mobile and desktop checks preserved the draft and reference removal/focus behavior. See `docs/design/global-app-concept/catalogue-reference-validation.md` for exact boundaries and evidence. The temporary database expires on 10 September 2026; the local launcher refuses an expired or unexpected branch.

### Contextual media continuation

`MediaActionPanel.client.tsx` is callback-driven presentation shared by the full Media collection, gallery result actions and destination reference confirmation. Modal library pickers retain their independent selection workflow. Media page search/pagination and saved/generated caches remain in `useLibraryPageData`; card previews never replace originals in action payloads.

`media-handoff.ts` keeps one pending request in session storage, bound to the account, an opaque navigation token and an image/video destination, with a ten-minute expiry and a 32 KB bound. `useMediaHandoff` consumes it once. Private original URLs never enter navigation queries. The image destination confirms an explicit new/replacement slot through `useImageReferenceSlots.handleLibrarySelect`; the video destination uses the existing recent-reference role, metadata and budget validation before insertion. Neither path changes a draft merely by opening the confirmation panel. Unsupported model roles remain explained and disabled.

Gallery media reuse requires a proven original (`originalUrl` for local image members, canonical render IDs for historical images, or video originals). A job-filtered authenticated recent-output read resolves its exact ready output identity before staging, so required metadata still uses the existing owned-output endpoint. A thumbnail-only or not-yet-persisted result does not become a generation input. Preview, main-result settings/save/copy and grouped output behavior retain their existing callbacks.


### Reference selection and creator options

`ReferenceLibraryPicker.client.tsx` owns the focused selection presentation requested by the video `AssetLibraryModal` and route-local `ImageLibraryModal`. `AssetLibraryBrowser` routes only callers with the explicit `selection` contract to this grid; full Media and tool-specific browser contracts retain their owners. The reference manager uses `WorkspaceReferenceInventory` to expose every role with its count/capacity, initially showing compatible images without changing input state. The compact picker header identifies the target role/slot and schema capacity; search, source coverage, upload and refresh remain above a bounded thumbnail body. A fixed footer exposes the chosen state, Clear, Cancel and Use. Destructive library management stays in Media, separate from removing a reference from the draft. Tool creation shortcuts remain in product navigation rather than interrupting selection.

Normal library choices are staged single selections. Selection is keyed by destination constraints, slot and source, and confirmation rechecks the current asset identity and exact original URL. Confirmation awaits the insertion callback, blocks duplicate submits and closing while busy, and never closes itself on a successful promise: only the existing insertion owner closes after acceptance. Video format/role/budget rejection messages are also returned to the panel; image rejection leaves the selection open. No bulk loop is applied to a single-reference callback. Upload still submits directly through the existing upload and insertion owners. Character selection preserves immediate toggles, its existing selected-ID mapping and capacity; Done closes without undoing already-applied choices.

Video, image and audio library dialogs body-portal inside `app-experience` and use `useAccessibleModal` for body lock, initial focus, Tab/Escape and opener return. Disabled fieldset descendants are excluded from modal focus recovery. The reference manager releases its modal before opening the library; sparse indices and replace/remove callbacks remain intact. Stored image thumbnails bypass public optimization. The audio source picker preserves immediate source selection and exact `GeneratedSourceVideo` payloads, uses lazy stored posters (or a placeholder), and never autoplays its collection.

Creator options remain the existing immediate or staged settings owners: `SettingsAdvancedPanel` retains seed/lock, guidance/influence, CFG, loop, generic schema and Kling/Seedance controls; `ImageAdvancedSettings` retains seed, mask, dimensions, search/thinking, generation limits and watermark. `SelectMenu` retains keyboard/value application behavior and its scoped portal language. Opening the Options disclosure does not apply defaults or discard staged settings. `app-advanced-content` styles these groups with dividers and 44 px controls. Model selection and media continuation retain the separate catalogue and `MediaActionPanel` flows.


Library data is account-scoped before selection: `useWorkspaceAssetLibrary` receives the existing video auth identity, synchronously hides previous-account assets/targets and invalidates late account/source reads and scoped mirror list writes. `useImageLibraryData` includes the current account and source URL in the SWR cache key, including character queries; changing account remounts the image picker and drops its staged choice. The shared existing auth hook supplies that image identity without changing authentication. Unmounted import dialogs do not apply late upload results to a new picker/draft. Focused DOM guards exercise account A→B, modal reopen, late A responses, source changes, original identity changes, immediate character toggles, acceptance/rejection and busy focus.
