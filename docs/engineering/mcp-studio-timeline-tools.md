# MCP Studio timeline tools

The source implementation adds two tools to the isolated Studio branch. Public registration still defaults to the existing disabled `studioMontageCreation` publication flag. Tests may explicitly set `studioTimelineEditing`; no production publication setting changes.

| Tool | Input | Result | Authority | Effects and recovery |
| --- | --- | --- | --- | --- |
| `get_studio_timeline` | Owned connected `projectId`, optional exact `sequenceId` | Saved sequence/revision, frame rate, clip and media-reference identities, gain, locks and mute state | Valid server-derived OAuth principal and client ID, then canonical connected project ownership | Read only. No original URLs, graph state, credentials, generation quote or charge. Omitted sequence selects the active sequence. |
| `edit_studio_timeline` | Owned project/sequence, current `expectedRevision`, exact `idempotencyKey`, one insert/trim/move/remove/gain command | Canonical edit receipt with saved revision and actual resulting clip timing | Valid server-derived OAuth principal and client ID, then the same project aggregate lock and ownership check used by session edits | Saves one edit through the existing command owner. Original media remain intact. Exact retries recover one stored receipt; changed content with the same key fails. Revision conflicts instruct the agent to reread and preserve manual edits. No generation or export charge. |

The [OAuth adapter](../../frontend/src/server/agent-api/studio-timeline.ts) does not impersonate a Studio session. It derives the internal OAuth actor after validating the principal; tool arguments never carry user identity or authorization origin. The canonical [edit command](../../frontend/src/server/studio/conversation-edit-command.ts) accepts reused OAuth outputs only when the exact output and job are owned by that account, ready/completed and not hidden, with source rows locked until the edit commits. Session edits retain their existing accepted project-scoped quote restriction. Asset refs still use the canonical owned-media resolver, storage ownership and measured-duration checks.

The shared [safe timeline projection](../../frontend/src/server/studio/conversation-timeline.ts) is consumed by Studio and MCP. It projects validated structural references and scalar edit facts, and drops malformed legacy reference objects instead of passing through arbitrary metadata. Its clips are edit identities, not private download destinations.

MCP [registration](../../frontend/src/server/mcp/tools/studio-timeline.ts) publishes strict input and output schemas matching `structuredContent`. Read annotations are `readOnly=true`, `destructive=false`, `idempotent=true`, `openWorld=false`; edit annotations are `readOnly=false`, `destructive=true`, `idempotent=true`, `openWorld=false`. SDK transport schemas use Zod v4 and the adapter reparses every edit with the existing canonical command schema. No external provider, rendering or billing pipeline is introduced.

Qualification is English and local: [real MCP plus PostgreSQL coverage](../../tests/mcp-studio-timeline-postgres.test.ts) proves scope isolation, rejected identity arguments, registration gating, schema/results, exact retries, cross-client/manual revision conflicts, completed-output reuse, rejected foreign/pending/hidden outputs and absence of generated quotes. [Projection coverage](../../tests/studio-timeline-safe-projection.test.ts) proves frame/mix/lock facts and private metadata exclusion. These tests do not qualify a hosted OAuth client, publish the tools or invoke paid providers. Source `638966f68` is separately installed into the localhost native pilot; its existing project was reopened without edits, model calls, renders or charges, as recorded in the [resume checkpoint](studio-conversation-resume-brief.md).

## Export tool inventory

The same isolated source adds three export tools. `studioExports` is an explicit runtime/test option; its default remains the unchanged disabled `studioMontageCreation` publication flag. These tools do not imply that Audio, montage or directory publication has been enabled.

| Tool | Input | Result | Authority | Effects and recovery |
| --- | --- | --- | --- | --- |
| `prepare_studio_export` | Owned saved project/sequence, current revision, quality (`draft`, `standard`, `high`), audio choice, exact retry key | Exact `StudioPreparedExport`: saved-cut identity, frame/duration/settings, price, expiry and confirmation requirement | Valid server-derived OAuth principal/client ID, then connected project ownership | Server builds the saved-cut snapshot. Preparation does not render or charge. Exact retry recovers one preparation receipt. Caller manifests, private URLs, tokens and account IDs are rejected. |
| `confirm_studio_export` | Owned project, exact scoped quote ID, `confirmed=true` after human approval | `{ok, export, reused}` with recorded job status and billing | Same OAuth user/client scope as preparation, owned live project, current cut or existing accepted job | Existing export pipeline authorizes, reserves and launches one render. Accepted retries recover the saved job even after later manual edits; stale first confirmation requires fresh preparation and approval. Worker/reservation internals remain private. |
| `get_studio_export` | Owned project and exact scoped quote ID | `{quoteId, export}`; null before acceptance, otherwise saved status, price and completed artifact delivery | Same OAuth user/client scope as preparation and owned live project | Read only; never renders, charges or retries. A private completed artifact obtains fresh temporary GET access through the existing owned read-grant owner. Delivery failure preserves completed status and billing with `artifact:null` and `artifactDelivery:"unavailable"`. |

The [OAuth export adapter](../../frontend/src/server/agent-api/studio-export.ts) reparses with the [canonical export contracts](../../frontend/lib/studio/conversation-export-contract.ts) and delegates preparation, confirmation and observation to the [shared command owner](../../frontend/src/server/studio/conversation-export-command.ts). The adapter never stores a second quote, estimate token, caller-authored cut or billing algorithm. Host creative decisions remain with the agent.

[Export MCP registration](../../frontend/src/server/mcp/tools/studio-export.ts) publishes strict input/output schemas matching `structuredContent`. Prepare annotations are readOnly=false/destructive=false/idempotent=true/openWorld=false; confirm annotations are readOnly=false/destructive=true/idempotent=true/openWorld=true; observe annotations are readOnly=true/destructive=false/idempotent=true/openWorld=false.

A Studio cookie-authenticated artifact path is not delivery access for an OAuth host. The adapter validates the canonical original's allowed host and owned storage prefix, then requests a 300-second GET grant from the existing [media-security owner](../../frontend/src/server/timeline-exports/media-security.ts). Private canonical originals, estimate tokens and worker data are omitted from host results. Grants exist only in the outgoing response and are refreshed on observation; they are never written to preparation receipts. Approved public originals can remain canonical without a storage grant. Signer/source failure never authorizes a replacement render.

[Real MCP plus disposable PostgreSQL qualification](../../tests/mcp-studio-export-postgres.test.ts) exercises server-owned snapshots, strict schemas/annotations/gates, session/OAuth separation, user/client quote ownership, explicit confirmation, stale-cut rejection, accepted recovery, temporary delivery renewal and absence of grants in saved receipts. Estimate/submission/read-signing boundaries are doubles; this test performs no real billing or worker launch. [Read-delivery coverage](../../tests/mcp-studio-export-delivery.test.ts) uses the real canonical storage-prefix owner to reject foreign keys, unapproved prefixes/hosts, existing grants and unusable cookie-only destinations before signing. It also rejects stale artifacts on in-progress jobs and preserves truthful completed status when signing is unavailable.

The [native chat browser journey](../../tests/connected-studio-export-quote-browser-integration.test.ts) passes Chromium, Firefox and WebKit separately. It checks mobile Olive/Charcoal layout, no confirmation on mount, lost acknowledgement/reload, same-quote recovery, recorded billing and no resubmission after acceptance. Conversation/confirmation/status responses are intercepted for this UI journey; the owned project and saved timeline are real disposable fixtures. This is local UI qualification without a model call, real worker or physical phone.
