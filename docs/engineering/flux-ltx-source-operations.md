## Draft cache authority and quantity

`server/flux-draft-cache-store.ts` resolves one current successful owner/job/provider request and ready position0 output. The stored original URL and SHA must match authoritative output mediaFacts. Optional sourceOutputId and Studio asset provenance narrow the same identity. `server/flux-draft-provenance.ts` accepts a closed private union: one exact completed native provider attempt; or the standard Fal writer's exact native endpoint/request SHA256 persisted with its accepted request ID in the enqueue row; or a strict historical canonical video request with native mode and consistent enqueue input summary. Both queue paths require the exact current provider request's later completed row. The writer hashes the final server-built request, independently of Site, MCP or Studio snapshot presentation. Historical web snapshots without this proof remain ineligible. An import marker, conflicting attempt, Extend/Enhance endpoint, incomplete canonical references or missing/ambiguous queue proof fails closed. Arbitrary client metadata, guessed GET endpoints and caller cache URLs are never authority.

Queue provenance persists explicit event IDs and a request/snapshot digest; `attemptId` is null rather than a fabricated historical attempt. Every prepare/quote/submit resolves current ownership, URL, SHA and private provenance again. Persistence locks current job/output and authoritative proof rows, then compares the same identity inside the transaction. Existing attempt cache fingerprints remain readable unchanged. The public picker carries only owned job/output IDs and preparation state; it exposes neither queue evidence nor cache grants.

`server/flux-draft-cache-recovery.ts` reads the exact terminal native Draft request via a separate SDK client with no retries, only the exact status/result GET URLs, no redirects, a30second deadline per request and2MiB response cap. Completed status must identify the same request. A conflicting result request ID is rejected; the SDK may report an empty ID when its response header is absent, in which case the exact bound GET/status identity and decoded pair proof remain mandatory. Provider video and cache must be HTTPS fal.media URLs. It downloads provider and current owned originals through shared bounded transport, compares decoded frame/audio identity and timing, and verifies stored original SHA. Delivery remux can differ in binary bytes. No submit or enhancement call exists in recovery.

Admission applies **before origin lookup, provider reads, downloads or decode**: one preparation per account and at most two per process, shared with excerpts/H3; busy fails429 and releases the slot on every exit. LTX retains its existing application upload limit30MiB. The shared preparation ceiling remains100MiB,180seconds,16megapixels,120fps for the shared probe; the narrower operation domain is then mandatory. Decode subprocesses have45second deadlines and bounded output; decoder threads are constrained. This is process concurrency admission, not a distributed account rate limiter or durable work queue.

Eligible native cache classes are text-to-video/draft, image-to-video/draft, first-last-frame-to-video/draft and keyframes-to-video/draft. **Draft Extend caches remain unqualified**: cache-to-continuation/output semantics need separate evidence. Existing native Draft Extend still works.

The deterministic customer quantity is the exact measured video duration of the qualified owned Draft, with its actual fps retained. An explicit **application admission/customer tariff domain is positive measured seconds up to21 inclusive** for those native Draft classes. Provider requested duration ends at20seconds, but there is no per-job integer requested-duration cap.20+1/24 at24fps and20.04 at25fps qualify if paired; outliers/malformed facts fail before quoting/charging. This21second bound is a conservative application qualification guard, **not a provider output maximum or invoice rule**. Draft caps publish no fps; the keyframe index×24 rule does not establish arbitrary output/container timing. The real supplied pair verified241identical decoded frames,24fps,10.041667seconds despite different binary containers and rounded stored duration10.042. This sample proves that pair only.

FAST admission reads the actual local-byte probe's ISO-BMFF major brand in addition to the shared canonical MIME. The display/upload probe deliberately still labels QuickTime MOV as `video/mp4`; that label, an `.mp4` filename or a declared MIME is not container proof. The operation admits byte-probed MP4 demuxer metadata only with supported MP4-family major brands (`isom`, `iso2`–`iso9`, `mp41`, `mp42`, `avc1`, `M4V `, `MSNV`, `dash`, `cmfc`, `cmfs`). QuickTime `qt  `, unknown or missing brands request a compatible copy. This conservative application qualification does not rewrite the original or assert a supplier brand allowlist. LTX and legacy readers retain their existing MIME/format behavior.

FAST's4096-character limit belongs to operation capabilities and is checked before canonical pricing/quote persistence and in Site request admission before reservation; the final wire builder repeats the check. LTX Reframe operation inference occurs before both Studio prompt-schema validation and pricing-scenario prompt selection, so omitted/null/explicit operation all accept the required empty prompt.

Unknown expiry is represented explicitly and is allowed. Known missing/null, expired or invalidated caches reject Enhance. Availability uses a public-DNS-pinned GET with an explicit no-redirect option and one30-second application deadline covering DNS, connection and first nonempty body chunk; expiry cancels the response and aborts the connection, and late DNS answers never open a connection. Success cancels the response immediately; no HEAD requirement and no invented TTL. Reachability is not a supplier acceptance guarantee. This policy is specific to cache availability: unrelated shared transport callers keep their existing at-most-three-public-redirect default, including ordinary media downloads during paired recovery; recovery status/result SDK GETs separately forbid redirects.

Real preparation binds original bytes/provenance through a legitimate durable-copy URL change and rechecks before and after promotion; changed original or copied bytes fail.

Public-safe binding includes source job/output, a fingerprint, exact duration, quantity policy and known/unknown expiry. The private URL remains only in `flux_draft_cache_sources.qualified_source` and server-only provider materialization. It is redacted from provider snapshots/diagnostics and absent from public assets, request hashes, history, reuse settings and public quote payloads. Source/ownership/attempt/output/fingerprint/availability are revalidated for quote, confirmation, reservation execution and immediately before dispatch. Confirmation uses only the bounded availability read, never recovery/decode. Accepted-job recovery returns the existing job instead of paying again.

## Completion order, explicit recovery and migration

Draft webhook completion first persists its original media/output, successful job state, provider terminal state, financial outcome and lifecycle logs through existing owners. Only at the very end does optional cache recovery run, outside settlement transactions. Failure, missing cache, busy admission or timeout is swallowed with a safe job-only diagnostic and cannot undo successful Draft delivery, trigger generation or affect its independent charge. If output persistence is not yet ready, cache qualification fails conservatively. The already completed job remains readable during optional work; request timeout can leave cache absent and the explicit retry action below supplies recovery.

`POST /api/jobs/{jobId}/draft-cache` is the explicit on-demand action after delivery. It requires authenticated owner resolution, exact same-origin Origin and rejects cross-site fetch metadata. The path supplies a bounded safe job ID; request-body URLs/cache fields are ignored and have no authority. The shared admission starts before recovery I/O. Response is `private,no-store`, containing only enhanceable/public-safe binding or cache_missing. Other failures return409 with generic unavailable wording; busy returns429; no private provider errors are serialized. It never charges, submits, creates a library asset, rewrites a Draft result or changes wallet state. Repeated successful recovery writes the same paired fingerprint idempotently; concurrent requests are rejected before I/O in one process and the database job/output lock plus conflict predicate prevents replacement across processes. Changed identity, invalidation or known expiry refuses replacement. Repeated retries can repeat bounded verification; there is no persisted work queue.

Migrations79 then80 are explicit deployment/operations prerequisites, **never a read-route/module/bootstrap action**. Apply through reviewed migration operations outside live read paths, after confirming target and application DB role. Migration79 creates the private paired-cache table; additive migration80 upgrades existing tables with nullable attempt IDs and constrained provenance discriminators without job/attempt backfills. Both revoke PUBLIC privileges. The owning application database role performs its narrow owner-scoped reads and writes; no anonymous/authenticated browser role receives grants and no public asset projection is added. A separately provisioned application role needs only table SELECT/INSERT/UPDATE (DDL remains operational); validate effective inherited grants in preview. This is server-authorized private storage, not a client-facing RLS API. Missing migration fails Enhance/recovery closed and leaves Draft delivery valid. No historical backfill or cache inference runs automatically. Root owns preview migration and recovery qualification; this implementation made no service/env/production writes.
