# Milo workflow chats

The generator keeps one active chat per authenticated account, surface and visible workflow. Create, Modify, Extend, Reframe, Retake, Keyframes and References are distinct video scopes. Image Create/Edit and audio Voice/Music/Song/SFX/Ambience have their own scopes. Changing the generation model or implicit provider input mode within Create keeps that chat and invalidates an obsolete suggestion.

## Ownership and restoration

`prompt-assistance/session.ts` owns workflow validation and draft canonicalization. `server/prompt-assistance/sessions.ts` projects a bounded display snapshot through the authenticated, no-store session GET. It returns completed turns, the working suggestion/fingerprint and an unresolved request ID, never private reference URLs, raw provider input or billing context. Reads cannot renew sessions or charge credits. A first successful completion renews the existing 24-hour expiry; replay and failures do not. The existing 100-request cap remains.

`usePromptAssistanceTransport` owns the account/workflow lifecycle. Versioned sessionStorage records contain the active UUID, unresolved identity, unsent message and locally edited proposal. They do not contain the transcript or reference URLs. The snapshot rebuilds conversation history; SHA-256 of the canonical current draft protects suggestion application after model/settings/reference changes. Loading is read-only. Scope changes and aborts fence late callbacks.

For qualified settings review, Send captures a bounded baseline before the message POST: original request identity, canonical draft digest, hard-context digest and known scalar settings. That proof survives a reload while the reply is pending. Restoration checks the same request's read-only status and terminal proposal text against the session snapshot before validating the captured context; a text-less reply cannot lend its proof to an older working suggestion. Hard-context changes revoke the pending proof as well as completed proof, and local epochs fence late digest writes. Completed local proposal persistence replaces the pending baseline. Missing, corrupt, legacy or mismatched evidence never gains review permission from the current draft. This path neither repeats a model call nor changes Apply/Undo or reviewable-control ownership.

The same tab restores its active chat after reload. There is no history picker or cross-device recovery. New chat rotates only the active conversation and analysis scope; the manual editor, model, settings and references remain. Exhausted/expired chats retain their replies and suggestion for review until explicit New chat. An unsent retry message survives that transition. Pending exchanges or reference analyses block reset, including their persisted identities before the recovery component mounts.

Deployed legacy clients used broad surface scopes. On first encounter, only their unresolved exchange or analysis identities cross into the new storage. They are settled under the original IDs without importing a mixed transcript or permitting new messages against that old scope. The user then starts a new workflow chat. Recovery never automatically dispatches another model call or repeats an analysis confirmation.

## Language

Milo's conversational reply honors the most recent applicable explicit reply-language instruction, including an ongoing preference still available in the conversation context. Otherwise it follows the language of the user's current own instruction, separately from quoted or supplied material, the editor and requested scripts/lyrics. If that language is unclear, it keeps the established conversation language; UI locale is only the last fallback.

The provider receives the latest eight completed exchanges before the current message. A reply-language preference outside that context is not retained by this policy, even when its earlier message is still displayed in the chat. This clarification adds no persistent preference or translation of stored replies.

Proposed-text language is chosen separately. Visual generation instructions default to English, including revisions of drafts in another language. Literal dialogue, captions, signage and names retain the requested wording/language. Voice scripts and lyrics retain their intended spoken/sung language. An explicit alternative instruction language is honored where the generation model supports it; model-specific English-only requirements remain authoritative. These instructions are shared across Lite, Standard and Max; underlying model names stay out of product copy.

## Creative constraints

Milo should preserve each negative constraint's intended scope. A specific exclusion must not become a ban on related content, and an element that is unnecessary is not automatically forbidden. For example, an image that communicates without a slogan does not imply excluding every other visible word. Explicit exclusions and supported setting constraints remain authoritative; unspecified creative details still allow reasonable choices.

This policy belongs to the shared provider instructions for every assistance level. Request transport and destination decoding preserve the supplied context and valid proposed text without a keyword filter. Offline scope fixtures check that boundary and policy inclusion; they do not establish real-model semantic compliance.

The session and live PostgreSQL tests exercise real disposable PostgreSQL, ownership/scope fences, no-store reads, minimal snapshots, completion-only expiry, replay, failed/pending requests and the session cap. Chromium regressions cover mode/account switching, reload, edited suggestions, New chat, stale context, legacy recovery, failed recovery, a completed 100th request, read-only hydration and expired/legacy reference analysis recovery.

Usage across these four checks was 9,332 input and 1,169 output tokens (2,874 cached input). They used direct test provider calls and did not modify a customer's credit ledger. This is sample output evidence, not a broad multilingual quality benchmark.

A fresh whole-change review found four important lifecycle defects. Each was reproduced and corrected: legacy pending identities, exhausted-session result loss, editable input during restoration, and retryable failure text lost during hydration. The 82-check focused suite passes after rebasing on main, including browser and PostgreSQL coverage. The four isolated Studio integration cases, production build and responsive visual check (320–1,440 px) also pass. This is combined evidence from the broad run and focused reruns, not a claim that the entire suite was rerun green in one invocation on the final commit. Final CI remains the merge gate; no new database migration is required by this change.
