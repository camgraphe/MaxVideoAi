# Luma Ray 3.2 controls and generation continuity

Source candidate, 24 October 2026. No provider render or operational tariff activation is implied by these contracts.

`src/lib/luma-edit-controls.ts` owns the browser projection of saved Modify controls. Automatic hides and omits manual inputs while retaining them in editor state. Manual permits a strength preset together with pose, depth, normals, trajectory and face controls. Each signal distinguishes provider default (omitted), On and explicit Off (`enabled:false`). Legacy face=false and pose=off retain their old omitted semantics. The direct payload builder validates the effective request and the submission owner stores a redacted `effectiveControls` summary from that built payload. It contains neither prompt nor source URL/ID and labels its evidence `built_payload`; it does not claim provider quality or identity preservation.

Creation keyframes are an optional text-to-video workflow: 1–64 images paired with unique nonnegative integer frame indexes. Canonical reference slots preserve caller order, including repeated images at distinct indexes. Start/end image workflows remain separate. Creation keyframes require direct Luma access and never fall back to fal. Modify keeps its qualified 18-second source domain; Reframe, HDR and EXR creation keep their existing contracts.

Extend uses an application `sourceJobId` (optionally exact `sourceOutputId`), never a public provider generation ID or uploaded URL. `generation-luma-lineage.ts` owns the bounded actor-scoped relational check: completed Ray 3.2 direct job, exact completed provider attempt and matching ready original video output. A saved media asset is optional; when supplied it must map to the same owned output and remain available. Administrators receive no ownership bypass. Hidden, missing, mismatched, HDR/EXR and incomplete provenance fail closed. There is no invented provider-ID expiry rule.

Prepare, transactional confirmation, Site preflight and new submission resolve this authority. Quotes bind owner/job/output/provider/attempt identity through a stable fingerprint that excludes expiring URLs. Confirmation and the final submission revalidate it. Accepted quote/job recovery occurs before fresh source validation, so source deletion does not authorize or require another render. Studio first checks attachment/project authority, retains exact job-output provenance, and revalidates materialization without promoting the source to the library.

Direct Extend sends exactly one generation anchor: forward=`start_frame`, backward=`end_frame`. It accepts SDR and five new seconds only; backward loop, additional frames and uploaded sources are rejected. No automatic append/prepend is planned while output layout remains unverified. Completion leaves the output's legacy duration unset and measures artifact timing through `hydrateOwnedVideoMediaFacts`; Studio insertion reads measured media facts. The job's five-second billing duration is not proof of artifact duration.

`luma-extend` has a separate operation tariff selector and no legacy Create or percentage fallback. Published reference facts are fixed 15/30/120 cents at 540p/720p/1080p. `server/pricing/luma-extend-tariff-proposal.ts` is read-only maintenance preparation: loaded effective policy is passed through the canonical standard calculator, yielding 20/39/156 cents under the reviewed 30% policy. It rejects existing selectors and binds the proposal to current grid/policy/revision. Literal cell activation belongs to bounded, reviewed tariff maintenance, with exact-candidate CI and transaction fences. Supplier invoice reconciliation and timeline layout qualification are separate from these authorized retail cells.
