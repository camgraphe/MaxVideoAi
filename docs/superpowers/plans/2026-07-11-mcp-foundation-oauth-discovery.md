# MaxVideoAI MCP Foundation, OAuth, and Discovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose an authenticated, universal remote MCP endpoint with OAuth 2.1, account discovery, public model listing, and deterministic model recommendations, without enabling provider calls or wallet mutation.

**Architecture:** Keep the public acquisition URL at `maxvideoai.com/mcp`. Rewrite only `api.maxvideoai.com/mcp` to an internal Next.js route at `/api/mcp`. MCP handlers call a transport-independent `agent-api` facade. Supabase-specific OAuth and bearer-token details remain inside a focused adapter that emits a normalized `AgentPrincipal`.

**Tech Stack:** Next.js 15 App Router, TypeScript, `@modelcontextprotocol/sdk` 1.29.0, Supabase OAuth 2.1/PKCE, Neon/Postgres, Zod, Node test runner.

## Global Constraints

- Keep `FEATURES.mcp.transport`, `FEATURES.mcp.oauth`, and `FEATURES.mcp.discovery` disabled until host smoke tests pass.
- Never authorize from `user_metadata`; derive `userId`, `clientId`, and verified-email state from validated access-token claims and the Auth user record.
- All authenticated MCP responses use `Cache-Control: private, no-store` and never contain tokens, raw claims, SQL, or fraud signals.
- Do not add provider submission, quote creation, wallet debit, upload, or trial behavior in this plan.
- The main-domain `/mcp` page is reserved for the acquisition plan; no `route.ts` may occupy that segment.
- Supabase OAuth Server is beta. Contain its methods behind `frontend/src/server/mcp/oauth-adapter.ts` and add contract tests before upgrading the client library.
- Preserve the user's unrelated Studio QA changes.
