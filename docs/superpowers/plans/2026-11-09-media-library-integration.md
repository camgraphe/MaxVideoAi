# Media Library Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate the user-approved compact common image/video/audio library, viewer, selection and organization into the actual product while preserving its existing workflows.

**Architecture:** Keep SWR and the current authentication, media identity, upload, destination, generation and Studio owners. Introduce owned organization state and a bounded common browse projection, then adapt the shared browser/viewer/pickers rather than replacing the existing business actions with prototype examples. New Trash is reversible library visibility: it never calls the old storage-releasing DELETE and never deletes generation history or existing Studio usage.

**Tech Stack:** Existing Next.js/React 18/TypeScript/SWR/PostgreSQL; qualify the prototype's pinned React Aria Components 1.22.1, Yet Another React Lightbox 3.33.0 and Uppy Core 6.3.1/React 6.1.1 inside the production frontend. Use existing media delivery and multipart upload adapters.

**Spec:** `experiments/media-library/integration-audit/INTEGRATION.md`, with its linked library/tool/delivery parity tables; the approved visual reference is `experiments/media-library/prototype`. The user explicitly authorized continuation on 2026-11-09 with “Okay, go on.” Implementation is authorized locally; production release is a separate action.

## Global Constraints

- Work only in the existing isolated `codex/media-library-prototype` worktree. No email, paid generation, live customer data mutation, production migration, merge or deployment.
- Preserve public and authenticated URLs, `view=saved/review`, `kind` and `job` deep links, account isolation, EN/FR/ES, all existing available actions and model-derived field/role limits. Prototype limits 4/12 are not product limits.
- Keep internal mutation IDs, canonical asset/job-output refs, original URLs, measured facts, and transient read grants distinct. A display URL is never media identity or a generation source replacement.
- All list reads remain bounded (default 30, maximum 100); filters precede limit/cursor. Never fetch the entire library to implement a local filter or total. GET performs no schema/bootstrap/probe/repair writes.
- New collection names: trimmed, 1–120 characters. Explicit bulk mutation: at most 500 references. A server-frozen all-results selection: at most 10,000; exceeding this fails honestly without partial selection or mutation. Snapshot lifetime: 10 minutes; no new media joins a snapshot.
- Trash affects list/picker visibility only and preserves bytes, canonical ownership, Activity and existing references. Restore is owned and idempotent; unavailable/permanently deleted underlying records must not claim success. No purge or automatic retention policy in this implementation.
- Favorites, collections, memberships, Trash and global selections must be server-owned and account-scoped. Organization keys must remain stable across grants and canonical/legacy/promoted projections without conflating distinct outputs.
- Mutations revalidate ownership and current availability, return truthful succeeded/failed outcomes, and update all relevant account-scoped caches. Late responses cannot resurrect hidden rows or overwrite another owner/selection.
- Refresh private read access at most once per failed read attempt, fenced to owner and canonical source. No signed/private URLs through the public image optimizer; no remote encoding or schema work in browser/GET.
- Only the active AV reader mounts and plays; opening/changing/closing releases previous playback. Initial grid loads thumbnails/placeholders. Original download, exact inspection and provider references retain exact originals.
- Follow root/nested AGENTS, architecture contracts and disposable PG17 helper. Attach comparable local media/network evidence and clearly distinguish fixture results from production performance.

## Review Focus

1. Real API rows with `id != assetId`, audio duration/facts, multiple outputs and legacy-only rows must survive every adapter; Task 1 tests these shapes.
2. A saved copy, recent output and legacy mirror must share organization where they represent the same source; distinct output versions and another owner's rows must stay independent; Tasks 2–3 test real SQL.
3. Deletion/restore/favorites/collection changes must survive filter changes, pending old responses and account changes; Task 4 exercises real SWR owners.
4. Expired private grants, a failed refresh, a changed reader and native first-Play must retain identity and recover at most once; Tasks 4 and 6 test lifecycle and transport boundaries.
5. Ordered multi-selection, single replacement, immediate Character toggles, refused insertion and popup return must preserve actual drafts and field budgets; Tasks 1, 5 and 7 exercise actual owners.
