# NINE-01 native evidence admission — design

## Intent and existing authority
Admit the nine real completed external Kling base clips without inventing application generations, rewriting accepted provider inputs or weakening legacy fal.media recovery. The delegated correction explicitly authorizes ordinary implementation, branch/PR preparation and independent review without another design approval. No upload, apply, migration, remote merge, activation, tariff, provider POST or publication belongs here.

## Approach chosen
Implement one opt-in Kling-only evidence profile, `nine01-native-v1`, with a strict typed private evidence bundle read through the existing operator CLI's explicit journal argument. Read real native files and original hash-chained event positions directly. A canonical summary is derived for immutable import provenance; original events and files are not renamed or changed. The legacy journal stays the default.

For the profile only, read reference bytes through a renewed exact-object signed GET using the existing trusted storage signer, not by fetching the historical untrusted URL. Verify the original historical grant, accepted source body, approved staging manifest/registration, object key/hash/master, ordered slots, owner binding and storage target first. Historical expiry is checked at actual submission; expiry now is allowed only when the retained exact object can be read and matches its original hash. The fresh read grant must itself be current and strictly target/key-bound. The fal.media allowlist is unchanged for ordinary imports.

Alternatives rejected: rewriting the raw journal into pretend original accepted/recovered events loses native provenance; globally allowing S3 URLs expands SSRF; moving references to fal.media and changing the accepted input falsifies the accepted request. A generic multi-provider evidence framework is unnecessary.

## Narrow boundaries
- Scope: NINE-01 base operations only, Kling ref2v, actual image-only 720p16:9 source shapes. Reserve/retake operation must have its own later qualified receipt; never replace the base silently.
- Staging namespace remains the already authorized editorial/drafts/launch-media batch/owner-token/content-hash key. The staging owner token is not an app UUID. Bind it explicitly to the real import owner; authoritative authorization remains canonical admin + owned media DB checks.
- Native bundle binds the manifest input by exact parsed JSON equality, raw request SHA, accepted response SHA/request ID, COMPLETED status ID/GET URLs, raw result SHA and original output hash. Original global journal chain and exact operation event sequences/files are mandatory. Nano events never become Kling evidence.
- Source local files are bounded regular private owner files outside Git/OUTREACH, with no symlink leaves or escaping paths. No implicit credential or neighboring-env loading.
- Network reads are GET-only, no redirects, bounded bytes/time. Signed source grants are never generic fetch targets. Trusted bucket/region comes from the existing explicit CLI target; keys are independently reconstructed from the verified manifest.
- Preserve canonical settings, private/nonindexable external_not_billed, wallet/payment/timing guards and all legacy imports. Persist compact native proof digests/positions with the immutable externalImport object, not a made-up receipt or SDK identity.
- Reuse acquired original/preview decode proofs for Studio linkage; no repeated whole-film decoding/listening claim.
- Preserve old green heads9a05/420b. This patch starts at9a05 in a separate worktree/branch.
