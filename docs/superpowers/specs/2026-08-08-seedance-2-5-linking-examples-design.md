# Seedance 2.5 — menu comparison and examples linking design

**Date:** 2026-08-08  
**Status:** approved

## Goal

Strengthen Seedance 2.5 internal discovery from the global comparison menu and
the Seedance examples landing page without making the examples hero taller or
delaying access to the videos.

This is internal linking work. It does not include LinkedIn publishing, Search
Console actions, paid generation, production environment changes, push, or
deployment.

## User-facing design

### Comparison dropdown

- Add one entry only: **Seedance 2.0 vs Seedance 2.5**.
- Put it first in the comparison dropdown.
- Display the existing generic registry-style `New` badge.
- Keep the menu compact by replacing the current first Seedance 2.0 vs Veo 3.1
  entry rather than increasing the number of comparison links.
- Use the existing localized navigation/link machinery so the destination is
  `/ai-video-engines/seedance-2-0-vs-seedance-2-5` in English and the canonical
  localized comparison path in French and Spanish.

This comparison is preferred because it answers the clearest launch intent:
whether an existing Seedance 2.0 user should move to Seedance 2.5. The broader
Veo and Kling comparisons remain indexed and linked elsewhere.

### Seedance examples landing page

- Update EN/FR/ES metadata and existing hero copy so Seedance 2.5 is presented
  first as the current flagship workflow.
- Keep the hero concise and within its current visual footprint.
- Do not add a banner, card, CTA row, link cluster, explanatory panel, or any
  other element above the videos.
- Keep Seedance 2.0, Fast, Mini, and 1.5 Pro in the copy as supported or legacy
  context, without implying that their existing examples were generated by 2.5.
- Put Seedance 2.5 first in the model links/filters that already exist. Do not
  create a new row for it.
- Add the Seedance 2.0 vs Seedance 2.5 comparison only to the existing secondary
  next-step navigation below the gallery. Do not place it in the hero.
- Reuse the existing model-page link for Seedance 2.5; do not duplicate it with
  another prominent CTA.

## Architecture and data flow

- `frontend/config/navigation.ts` remains the authored owner of dropdown items.
  The existing desktop and mobile menu renderers consume the same item, label,
  badge, and localized href.
- `frontend/lib/examples/modelLandingData.{en,fr,es}.ts` remains the authored
  owner of localized Seedance landing copy.
- Existing examples-page builders remain responsible for model ordering and
  next-step links. Any ordering change must use the current data builder rather
  than route-local JSX.
- No new client component, layout container, or browser-only state is required.
- All links must render as normal crawlable anchors with concise destination-
  specific labels. No `nofollow` is added to the model or comparison links.

## Content boundaries

- Claims remain bounded to the published Seedance 2.5 contract: five workflows,
  4–30 seconds, 480p/720p, 16:9, 24 FPS, optional generated audio, and the
  documented MaxVideoAI reference limits.
- Copy must not claim that every gallery video is a Seedance 2.5 render.
- The page must not expose provider names, model IDs, internal pricing language,
  launch gates, or production operations.
- No LinkedIn content or terminology is added.

## Verification

- Navigation contract proves the dropdown contains exactly one new 2.5
  comparison entry, first, with `New`, and that the menu length does not grow.
- Desktop and mobile navigation tests prove they consume the shared item.
- EN/FR/ES content tests prove Seedance 2.5 appears first in metadata, hero copy,
  summary, and model ordering while older routes remain represented accurately.
- Examples architecture/SEO tests prove the comparison link is rendered in the
  existing below-gallery next-step section and not in the hero.
- A render/structure contract proves no new pre-gallery section or extra hero
  action row was added.
- Focused navigation, examples, i18n, SEO, and route tests pass, followed by the
  full repository validation and production build before deployment evidence is
  updated.

## Separate pre-deployment issue

The local preview exposed a self-redirect on canonical French and Spanish
marketing routes. That routing defect is not caused by this content/linking
design and must be diagnosed and fixed as a separate technical change before
production deployment.
