# Durable GA4 wallet payment delivery

The user approved the server queue identified in the analytics audit. Preserve payment fulfillment, existing live/consent/admin eligibility and GA4 parameter limits. Scope: canonical wallet `purchase`/`topup_completed` and existing `topup_refunded`; no direct-card expansion, historical replay or new revenue definition.

Persist two unique receipt/event intents within the receipt transaction. A savepoint isolates optional measurement failures; a version marker on newly inserted receipts permits a bounded recent-receipt repair if enqueue failed. Repair only versioned receipts, never old receipts or terminal outbox rows. Refund enqueue failures throw so Stripe retries the measurement handler; it does not modify wallet balances. Deduplicate refund snapshots by charge and cumulative refunded amount, retaining the signed event delta and timestamp.

A separate secret-authenticated production cron every five minutes claims at most 20 rows with SKIP LOCKED, a token and two-minute lease. Each HTTP attempt has a five-second timeout; four parallel workers stay below a 60-second route budget. Limit to eight attempts, exponential five-minute backoff capped at six hours, and 71 hours from original occurrence. Preserve timestamp_micros, client/session IDs and the existing explicit user-derived client fallback. HTTP 2xx means transport accepted, never ingestion. Google explicitly says not to retry a non-2xx HTTP response unchanged: mark it terminal for review. Network/timeout and configuration/eligibility unavailability are retryable. A crash after collector acceptance before acknowledgment can duplicate transport: no exactly-once claim.

Recheck current/legacy admin tables and stored cookie consent immediately before sending. Unknown role/schema errors defer without sending. The signed Stripe object creation time bounds the original checkout consent snapshot. A recorded denial, or any newer consent decision (even regrant), permanently suppresses that old intent. Missing persisted cookie choice falls back only to the original explicitly granted checkout snapshot, as anonymous consent is not account-persisted. Browser-only withdrawals never received by the server remain unobservable; document this limit. No consent mutation is needed.

Retain terminal dedupe tombstones but erase payload and user linkage on terminal completion. Expire pending rows before 72h. Store only bounded structured transport outcomes, never response bodies/secrets. Aggregate cron results and SQL monitoring include pending age, accepted/suppressed/dead counts, attempts and repair counts; OUTREACH receives no individual identifiers.

Additive Neon migration precedes code activation; it changes no balances or historical receipts. Rollback stops the cron using an enable flag while retaining evidence. Tests use disposable PostgreSQL and a fake collector, never real payments. Normal isolated branch → PR → all required CI → aligned Git deployment. OUTREACH documents observed results separately from the scheduled 48h GA4 verification.

Sources checked 2026-10-20: https://developers.google.com/analytics/devguides/collection/protocol/ga4/reference and https://developers.google.com/analytics/devguides/collection/protocol/ga4/sending-events .
