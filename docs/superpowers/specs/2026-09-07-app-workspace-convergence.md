# App workspace convergence

The approved concept in `docs/design/global-app-concept/` sets the visual direction, not a reduced feature set. The integrated product should be richer while retaining its matte workspace, readable typography, compact controls, visual media grid and contextual “continue with this media” actions. This increment precedes Studio integration.

## Required outcomes

- Creation: compact mobile Recents action beside the heading; refined local scrollbars, including prompt. Model picker becomes a legible family browser without a wall of metadata, nested scrollbars or loss of the real catalogue, legacy opt-in, search, unavailable reasons, keyboard selection, score/timing and capabilities.
- Media: a visual responsive collection, with compact search/kind/source/saved-generated controls. Import, pagination, server search, original downloads, saving and confirmed deletion remain. A discoverable media action panel offers only supported, connected reuse destinations. Recent reference role selection and generation compatibility remain authoritative.
- Activity: one initial chronological feed, with media/tool source filtering and honest loading/error/empty states. Preserve grouped outputs, preview, save, retry/status refresh and existing continuation/refinement/comparison actions. Avoid mounting seven initial feeds and seven skeleton rails.
- Tools: replace the old nested-card hub with a coherent visual collection of the five real tools, retaining descriptions that explain purpose and their actual routes.
- All touched screens: accessible light/dark treatments, visible essential actions, mobile touch targets at least 44px, no horizontal page overflow, bounded media loading and original assets retained for reuse/download.

## Boundaries

No model-policy, billing, provider, Studio or production-data changes. Existing route orchestration, SWR and media lifecycle owners stay in place. No fabricated price, score, timing, progress, media title, project count or unsupported destination. Prototype tools were placeholders: derive their finished presentation from the established visual rules and the real tools, rather than claiming a pixel-identical reference.

## Validation

Compare the real app with the concept using desktop and mobile screenshots. Exercise model families/search, media action panels and close/focus behavior, Activity source switching/pagination and tool navigation without paid operations. Record before/after Activity request/render evidence under comparable local conditions; distinguish dev compilation from application fetch time. Run focused behavioral/architecture checks, types, lint, build and full validation.
