Esta referencia describe el despliegue de solo lectura controlado y verificado el 2026-07-12. La conexión pública no
está disponible actualmente. Distingue el registro de tres herramientas cubierto por esa prueba alojada de las
funciones de referencias, cotización y generación ya implementadas, pero aún detrás de flags de publicación desactivados.

## Dirección MCP de producción

El valor de configuración universal es:

```text
https://api.maxvideoai.com/mcp
```

Es el recurso MCP Streamable HTTP, no una página web ni una API REST pública de uso general. No agregues tokens,
parámetros de consulta ni credenciales de usuario a la dirección. La autorización OAuth 2.1 es obligatoria cuando se
habilita el despliegue.

## Rutas verificadas por cliente

Las tres rutas siguientes son independientes. Una prueba aprobada para un cliente no sirve como evidencia para otro.
Última verificación: 2026-07-12.

### Claude Desktop 1.20186.1

La prueba alojada registrada usó un conector remoto personalizado. Agrega la dirección MCP de producción en Claude
Desktop y revisa los permisos de identidad `openid,email,profile` en la aprobación de MaxVideoAI que se abre en el
navegador. Las herramientas de solo lectura, la revocación y la reconexión pasaron. La renovación del token después de
su vencimiento sigue pendiente.

### Claude Code 2.1.207

La ruta local registrada es:

```bash
claude mcp add --transport http maxvideoai https://api.maxvideoai.com/mcp
claude mcp get maxvideoai
```

Abre `/mcp` en Claude Code para iniciar la autorización en el navegador. OAuth local, la revocación y la nueva
aprobación pasaron; una llamada alojada a las herramientas sigue pendiente porque el cliente de prueba no tenía una
sesión de Anthropic.

### Codex CLI 0.144.1

El flujo predeterminado para agregar la conexión solicita el permiso adicional `phone` y sigue bloqueado. Primero,
registra la conexión:

```bash
codex mcp add maxvideoai --url https://api.maxvideoai.com/mcp
```

Ese comando abre inmediatamente el consentimiento predeterminado. Cancela o rechaza ese consentimiento sin aprobar
`phone`, pero conserva la entrada registrada de MaxVideoAI. Después inicia por separado la ruta con permisos mínimos
que pasó la prueba alojada de solo lectura:

```bash
codex mcp login maxvideoai --scopes openid,email,profile
```

Tras aprobar solo esos tres permisos, verifica la entrada conservada:

```bash
codex mcp get maxvideoai
```

La aplicación y la biblioteca de Codex no han sido validadas. Su compatibilidad no se puede deducir de la evidencia de
Codex CLI.

## OAuth y acceso a la cuenta

OAuth 2.1 usa el inicio de sesión y el consentimiento en el navegador. El cliente recibe permiso para llamar las
herramientas publicadas de MaxVideoAI con la cuenta aprobada; no obtiene acceso a la base de datos, datos de pago ni la
contraseña. Si rechazas el consentimiento, la conexión queda sin autenticar.

Todas las herramientas del registro actual exigen OAuth. `get_account_status` devuelve el estado de conexión, el estado
del correo verificado, un resumen de la billetera, el estado deshabilitado de la prueba, los campos opcionales de
límite y la URL de conexiones de la cuenta. El correo se omite, igual que los datos de pago.

## Funciones implementadas detrás de flags desactivados

El código también contiene un flujo conectado protegido. Todavía no forma parte del registro público ni de la prueba de
compatibilidad alojada del 2026-07-12:

- `list_media` enumera solo las imágenes privadas listas del usuario autenticado, con vistas previas controladas.
- `create_reference_upload_link` crea un paso privado en el navegador, de un solo uso y válido durante 15 minutos. El
  token sin procesar nunca se almacena y la carga queda vinculada al usuario autenticado de MaxVideoAI.
- `prepare_generation` valida el modelo público y sus ajustes, verifica las referencias propias, calcula el precio exacto
  de la cuenta y guarda una cotización inmutable de corta duración, sin cobrar ni generar.
- `confirm_generation` exige confirmación explícita de esa cotización, aplica límites de gasto y envía el trabajo de
  forma idempotente. `get_generation_status` y `list_recent_generations` permiten recuperarlo.
- `create_topup_link` abre un paso temporal de facturación de MaxVideoAI sin recopilar datos de pago mediante MCP.

Estas herramientas no deben presentarse como disponibles hasta activar sus flags y volver a verificar el flujo alojado
completo en cada cliente compatible.

## Prompts e imágenes de referencia

Claude o Codex aclara la idea y redacta el prompt. También puede ayudar a crear una imagen de referencia adecuada con
sus propias capacidades de imagen. MaxVideoAI aporta los datos actuales del catálogo y diferencias factuales entre
modelos; no ejecuta otro modelo solo para reescribir el prompt.

Una imagen creada por el cliente puede entrar en el flujo protegido mediante `create_reference_upload_link`, o se puede
elegir una imagen privada existente con `list_media`. MaxVideoAI verifica el propietario y el formato ráster durante la
preparación y de nuevo durante la confirmación. La cotización inmutable conserva solo el ID estable del activo; la URL
interna verificada se materializa temporalmente para el proveedor. El registro público actual todavía no incluye
`list_media` ni `create_reference_upload_link`, así que el envío conectado no está disponible públicamente.

La ingestión directa de una URL HTTPS arbitraria no se presenta como terminada: aún faltan la descarga remota segura y
su verificación alojada. Las imágenes generadas también deben recibir siempre un `assetId` reutilizable antes de poder
anunciar un flujo circular completo de imagen a video.

## Precio, cotización, confirmación y estado de los trabajos

El producto web de MaxVideoAI enseña el precio mostrado antes de generar. Este despliegue de solo lectura no entrega un
precio exacto, no cobra la billetera y no envía medios. Estas funciones no están disponibles actualmente.
`recommend_models` no es una cotización.

El registro público no incluye `prepare_generation` ni `confirm_generation`. La implementación protegida prepara una
cotización inmutable, de corta duración y controlada por el servidor, además de exigir una confirmación explícita
separada antes de gastar. Como ese contrato no está publicado en este despliegue de solo lectura, no hay una huella ni
un vencimiento públicos de cotización que se puedan usar hoy. Esta guía no contiene ejemplos de precios estáticos.

Tampoco hay herramientas publicadas `get_generation_status` ni `list_recent_generations`. Su implementación protegida
devuelve datos de recuperación seguros, pero aún debe verificarse el renderizado y el polling en clientes alojados.
Sigue el trabajo en Trabajos del producto web de MaxVideoAI y recupera los resultados desde la biblioteca web. No se
publica un intervalo de polling MCP.

`create_topup_link` está implementado pero no publicado. La recarga de la billetera y el pago directo permanecen en el
producto web de MaxVideoAI. Una recarga correcta invalida la cotización corta anterior; prepara después una nueva exacta.

## Condiciones previstas para la prueba de Seedance 2 Mini

La prueba MCP no está disponible en el estado de publicación actual. Las condiciones previstas definen un derecho promocional único; no es dinero de la billetera ni un saldo reutilizable. Para ser apto se exige una cuenta OAuth apta con
correo verificado, ninguna prueba consumida previamente por ese usuario, ninguna restricción de la cuenta activa y
límites de frecuencia y controles de riesgo aceptables. Solo podrá usarse una vez por usuario si se publica esta
función.

El preset impuesto por el servidor es Dreamina Seedance 2.0 Mini (Seedance 2 Mini), texto a video, 5 segundos, 480p,
con ratio `16:9`, `9:16` o `1:1`, audio a elección del usuario y una salida. Ninguna entrada puede cambiar estas
condiciones. La herramienta de cuenta devuelve `trial.status: disabled` y no hay una herramienta de preparación o
reserva de la prueba en el registro publicado.

## Límites de gasto y seguridad de la confirmación

El resultado de la cuenta incluye `perGenerationCents`, `dailyCents` y `webApprovalAboveCents`. En la base actual de
solo lectura, cada valor es `null`: no existe un control de gasto MCP activo ni una acción que pueda gastar. Un valor
nulo no promete gasto ilimitado; la generación conectada no está disponible.

El texto del servidor no puede anular la aprobación automática que una persona configure en su cliente. Antes de
publicar las herramientas de pago, la cotización separada, la confirmación explícita, los límites del servidor, la
idempotencia y el paso de aprobación web ya implementados deberán superar la verificación alojada.

## Desconexión y revocación del acceso

1. Elimina o borra la conexión de MaxVideoAI en el cliente.
2. Abre [las conexiones de la cuenta de MaxVideoAI](/account/connections).
3. Revoca el acceso de ese cliente.
4. Comprueba que la siguiente llamada protegida exija una aprobación nueva en el navegador.

La revocación invalida el acceso; una reconexión no debe reutilizarlo en silencio.

## Privacidad y tratamiento de datos

- El correo de la cuenta se omite de los resultados de las herramientas.
- La auditoría solo permite datos generales de conexión, cliente, herramienta, resultado, superficie, modelo y error.
- El prompt, los tokens de acceso, los secretos, las URL completas de referencias, los medios privados y los datos de
  pago se excluyen de la carga de auditoría MCP.
- Las respuestas MCP autenticadas usan `Cache-Control: private, no-store`.
- El MCP no implica que un contenido generado sea automáticamente seguro para publicar o autorizado para uso comercial.

## Errores estables y recuperación

Solo se indican las fallas estables observables mediante el gestor de autenticación publicado o la envoltura activa de
las herramientas.

| Falla observable | Significado | Acción de recuperación |
| --- | --- | --- |
| `HTTP 401 / JSON-RPC -32001` | La solicitud protegida no tiene una autorización OAuth válida. La respuesta incluye un desafío `WWW-Authenticate` cuyo `resource_metadata` indica el descubrimiento del recurso protegido. | Deja que el cliente siga el desafío y completa la autorización en el navegador. Después de revocar, aprueba un acceso nuevo antes de reintentar. |
| `INTERNAL_ERROR` | Se ocultó una falla inesperada. | Conserva el `correlationId`, detén las llamadas repetidas y contacta al soporte de MaxVideoAI si el problema continúa. |

La validación MCP puede rechazar una entrada mal formada, pero esta guía no le asigna un código de aplicación
MaxVideoAI que el código actual no proporciona.

## Solución de problemas

### Se vuelve a solicitar autenticación

El acceso puede haberse revocado o vencido. Abre otra vez la conexión del cliente y completa una aprobación nueva de
MaxVideoAI en el navegador. Nunca pegues un token en la dirección MCP.

### Codex solicita más que los tres permisos de identidad registrados

Detén el flujo predeterminado. Usa el comando explícito `codex mcp login` anterior con `openid,email,profile`. La
evidencia actual no aprueba la ruta predeterminada.

### Claude solo muestra tres herramientas de lectura

Ese es el registro actual completo. No esperes acciones de generación, carga de referencias, prueba, cotización, cobro o
polling en este despliegue.

### Una recomendación no tiene un precio exacto

Es el comportamiento esperado. Continúa en el producto web de MaxVideoAI, elige ajustes compatibles y revisa el precio
mostrado antes de generar.

## Funciones fuera del alcance actual

- Una API REST pública de uso general o credenciales de API.
- Endpoints de callback para clientes.
- Pago directo o recopilación de datos de pago mediante MCP.
- Edición de video fuente, extensión de video o envío de un archivo de audio.
- Control de la timeline de Studio, secuencias, proyectos o exportaciones.
- Modelos ocultos, deshabilitados, administrativos o experimentales.
- Aprobación automática de medios para publicación o uso comercial.
