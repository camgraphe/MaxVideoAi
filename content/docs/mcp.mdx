This reference describes the local, controlled read-only package. Public connection is not currently available. The
five-tool discovery profile is covered by local contract tests; hosted OAuth, Codex loading, and Claude loading remain
unverified. Generation, upload, quotes, wallet debit, and trial capabilities remain behind disabled publication gates.

## Production MCP address

The universal configuration value is:

```text
https://api.maxvideoai.com/mcp
```

This is the MCP Streamable HTTP resource, not a browser page or a general public REST API. Do not add an access token,
query string, or user credential to the address. OAuth 2.1 authorization is required when the rollout is enabled.

## Local package and host verification

The shared local package contains thin adapters for Codex and Claude, but it is unpublished and is not an installation
guide. No hosted OAuth authorization, refresh, Codex rendering, Claude rendering, provider call, or marketplace
submission is verified by this branch. The intended OAuth 2.1 identity scopes are `openid,email,profile`; treat them
as design constraints until a hosted flow is tested.

## OAuth and account access

The intended, release-gated behavior is that OAuth 2.1 uses browser sign-in and consent. A host may then receive
permission to call the released MaxVideoAI tools for the approved account; it does not receive database access, payment
details, or the account password. Denying consent leaves the connection unauthenticated.

The local discovery registry requires OAuth for every tool. `get_account_status` returns account connection state, verified-email
state, wallet summary, disabled trial state, nullable spending-limit fields, and the account-connections URL. It omits
the account email and payment details.

## Implemented behind disabled publication gates

The current code also contains a gated connected workflow. It is outside the local five-tool discovery profile and
remains behind disabled publication gates:

- `list_media` lists only the authenticated user's ready private image assets, with controlled previews.
- `create_reference_upload_link` creates a private, one-use browser handoff that expires after 15 minutes. The raw
  handoff token is never stored; the browser upload is bound to the authenticated MaxVideoAI user.
- `prepare_generation` validates the selected public model and settings, verifies owned asset references, computes the
  account's exact price, and stores a short-lived immutable quote without charging or starting generation.
- `confirm_generation` requires explicit confirmation of that quote, applies account spending controls, and submits
  the job idempotently. `get_generation_status` and `list_recent_generations` recover its state and outputs.
- `create_topup_link` returns a short-lived MaxVideoAI billing handoff; it never collects payment details through MCP.

These tools must not be presented as live until their publication flags are enabled and the complete hosted path has
been reverified in each supported host.

## Prompts and reference images

Claude or Codex clarifies the brief and writes the prompt. It can also help create a suitable reference image with the
host's own image capability. MaxVideoAI supplies current catalog facts and factual model trade-offs; it does not run
another model merely to rewrite the prompt.

A host-created image can enter the gated workflow through `create_reference_upload_link`, or an existing private image
can be selected with `list_media`. MaxVideoAI validates ownership and raster type during preparation and again during
confirmation. The immutable quote keeps only the stable asset ID; only the verified internal media URL is materialized
temporarily for provider submission. The current public registry still has no `list_media` or
`create_reference_upload_link` tool, so connected reference transfer is not currently available publicly.

Direct arbitrary HTTPS-reference ingestion is not claimed as complete: remote fetch hardening and hosted verification
remain required. Generated image outputs also still need a guaranteed reusable `assetId` before a fully circular
image-to-video workflow can be advertised.

## Price, quote, confirmation, and job status

The MaxVideoAI web product shows the displayed price before generation. The local `calculate_project_budget` tool can
return a canonical-price project estimate for named proposals, including separately declared creative attempts. A
project estimate is not a quote: it does not reserve price or capacity, debit a wallet, or submit media.
`recommend_models` is not a price quote.

The public registry has no `prepare_generation` or `confirm_generation` tool. The gated implementation prepares a
short-lived, server-owned immutable quote and requires a separate explicit confirmation before spending. Because that
contract is not published in this read-only rollout, there is no public quote fingerprint or expiry to rely on today,
and this guide contains no static price examples.

There is also no published `get_generation_status` or `list_recent_generations` tool. Their gated implementation uses
safe recovery DTOs, but hosted client rendering and polling still require verification. Follow current work in Jobs in
the MaxVideoAI web product and recover completed output from the web library. No public MCP polling interval is published.

`create_topup_link` is implemented but not published. Wallet funding and direct payment remain in the MaxVideoAI web
product; a successful top-up invalidates the previous short-lived quote, so prepare a new exact quote afterward.

## Gated Seedance 2 Mini trial contract

The MCP trial is not available while its publication gate is off. The gated contract is one promotional entitlement,
not wallet money and not a reusable balance. Eligibility requires an eligible OAuth account with a verified email, no
prior consumed trial for that user, no active account restriction, and acceptable rate and risk checks. It is available
at most one time per user when the gate is enabled.

The server-fixed preset is Dreamina Seedance 2.0 Mini (Seedance 2 Mini), text-to-video, 5 seconds, 480p, one of `16:9`,
`9:16`, or `1:1`, audio user-selectable, and one output. No input may change those terms. The current account tool
returns `trial.status: disabled`; there is no trial preparation or reservation tool in the published registry.

## Spending limits and confirmation safety

The account result includes `perGenerationCents`, `dailyCents`, and `webApprovalAboveCents`. In the current read-only
foundation, each value is `null`: no MCP spending-limit control or spending action is active. A null value is not a
promise of unlimited spending; no connected generation is available at all.

Host-level automatic approval cannot be overridden by server copy. Before paid tools are published, the implemented
separate quote, explicit confirmation, server-side limits, idempotency, and web approval handoff must all pass hosted
verification.

## Disconnect and revoke access

1. Remove or clear the MaxVideoAI connection in the client.
2. Open [MaxVideoAI account connections](/account/connections).
3. Revoke the grant for that client.
4. Verify that the next protected call requires a fresh browser approval.

Revocation invalidates the grant; reconnecting must not silently reuse it.

## Privacy and data handling

- The account email is omitted from tool results.
- Audit events allow only coarse connection, client, tool, outcome, surface, model, and error dimensions.
- Prompt text, access tokens, secrets, full reference URLs, private media, and payment information are excluded from the
  MCP audit payload.
- Authenticated MCP responses use `Cache-Control: private, no-store`.
- The MCP does not imply that generated content is automatically safe to publish or commercially cleared.

## Stable errors and recovery

Only the stable failures reached through the published authentication handler or live tool wrapper are listed here.

| Observable failure | Meaning | Recovery action |
| --- | --- | --- |
| `HTTP 401 / JSON-RPC -32001` | The protected request has no valid OAuth bearer grant. The response includes a `WWW-Authenticate` challenge whose `resource_metadata` points to protected-resource discovery. | Let the client follow the challenge and complete browser authorization. If access was revoked, approve a fresh grant before retrying. |
| `INTERNAL_ERROR` | An unexpected failure was redacted. | Keep the returned `correlationId`, stop repeated calls, and contact MaxVideoAI support if the failure persists. |

Input-shape failures may be returned by the MCP protocol validation layer, but this guide does not assign them a
MaxVideoAI application code that the live code does not provide.

## Troubleshooting

### Authentication is requested again

The grant may have been revoked or expired. Reopen the client connection and complete a fresh MaxVideoAI browser
approval. Never paste a bearer token into the MCP address.

### Codex or Claude does not load the package

That is an expected release gate: this branch has no verified host loading. Do not treat the local package as a public
installation path; record the exact host, version, OAuth result, tool rendering, and refresh behavior before a claim.

### A local client shows five read-only tools

That is the complete local discovery profile. Do not expect generation, upload, trial, exact quote, wallet mutation, or
polling actions from this rollout.

### A model recommendation has no exact price

That is expected. Continue to the MaxVideoAI web product, choose supported settings, and review the displayed price
before generation.

## Current non-goals

- A general public REST API or API credentials.
- Customer callback endpoints.
- Direct payment or payment-data collection through MCP.
- Source-video editing, video extension, or audio-file transfer.
- Studio timeline, sequence, project, or export control.
- Hidden, disabled, administrative, or experimental models.
- Automatic approval of media for publication or commercial use.
